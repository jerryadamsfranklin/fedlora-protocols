# Neurocomputing Follow-up on Three Blocking Items

This note addresses the three blockers raised after Part 1/2/3 completion.

## 1) Communication mismatch (exact 2x vs Phase 1) — root cause

Status: investigated; root cause identified.

- The byte-accumulation logic is the same in both phases (`src/federation/server.py`): communication is tracked as upload + download bytes from actual tensor element sizes.
- The 2x ratio is not caused by a second add in the runner.
- The mismatch is caused by historical run-protocol drift:
  - Phase 1 CUDA reruns were produced at commit `7b95775` where `scripts/run_experiment.py` did not pass `lora.target_modules` into `FederatedLoRAModel`, so training defaulted to `q_proj,v_proj` (2 targets).
  - Part 1/2 runs were produced at commit `8cddb8b` after wiring `target_modules`, so training used `q_proj,k_proj,v_proj,o_proj` (4 targets).
- Evidence in run artifacts:
  - Phase 1 FLoRA run has `broadcast_bytes_per_client = 9011200`.
  - Part 1 Dolly FLoRA run has `broadcast_bytes_per_client = 18022400`.
  - Exact 2x corresponds to 2-target vs 4-target LoRA communication volume.

Implication: do not compare absolute communication MB between those two batches as if they were the same protocol.

## 3) FFA-LoRA non-IID alpha=0.5 outperforming IID on held-out delta

Status: investigated at seed level; effect is consistent, not random noise.

From `analysis/neuro_part2_baselines_holdout.csv`, paired by seed:

- FFA-LoRA `noniid_minus_iid` delta-loss:
  - seed 42: `-0.004689`
  - seed 123: `-0.006092`
  - seed 456: `-0.004523`
- FedIT `noniid_minus_iid` delta-loss:
  - seed 42: `+0.009213`
  - seed 123: `+0.012180`
  - seed 456: `+0.007249`

Interpretation (working hypothesis):

- Alpaca non-IID in this repo is generated by instruction-length proxy buckets (not semantic class labels).
- FFA-LoRA (A frozen from round 1) appears to benefit from this partition structure as an additional regularization signal, while FedIT shows the expected non-IID penalty.
- This should be documented as observed behavior under the repo's non-IID construction, not treated as measurement noise.
